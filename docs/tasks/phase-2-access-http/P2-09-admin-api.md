# P2-09 — Admin REST API

## Goal
Everything an operator manages — instances, credentials, workspaces, grants, tokens, users — through one validated, audited API.

## Scope
- `/api/admin/v1/*` with `@hono/zod-openapi`; error envelope `{ error: { code, message, field?, detail? } }`; status mapping 400/401/404/409/413/415/422/429/502/503.
- Break-glass admin token generated by `agility-bridge admin-token` (typed `ab_admin_…`, 256-bit), passed as `AB_ADMIN_TOKEN`/`AB_ADMIN_TOKEN_FILE`, kept as a digest in memory, compared in constant time, rate-limited on failure; non-generated values refused at boot; absent → 404 for the whole API.
- Instance origin and TLS trust immutable while credentials exist; changing them is owner-only, requires a recent sign-in (once sessions exist, P4-02) and revokes the instance's credentials and grants (THREAT_MODEL A14).
- Owner/admin guards applied to **every** writer of credentials, workspace defaults, Agility projects, tools and write settings.
- OpenAPI document served and the reference generated into docs.

## Acceptance criteria
- [ ] Negative authorization tests for every route and role.
- [ ] Tests: weak or hand-made admin tokens refused; an admin cannot change an instance origin; an owner change revokes the instance's credentials.
- [ ] Generated `docs/reference/admin-api.md` committed.
