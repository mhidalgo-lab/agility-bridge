# P9-29 — Agent Plugins manifest and agent-facing discoverability

## Goal
Agent-readiness scanners find agility-bridge. A scan of the author's site (which links here) reported "no Agent Plugins
manifest (plugin.json) found" and "no public repo with agent configs". The repository gets a spec-conformant Agent
Plugins manifest, AGENTS.md says how an agent *uses* agility-bridge (not only how to change it), and the README names
every manifest.

## Scope
- Root `plugin.json` per [Agent Plugins 1.0.0](https://agent-plugins.org/specification): `$schema`, `name`, version
  0.8.0, and the Claude Code manifest's description, author, homepage, repository, license and keywords. The spec has
  no config fields, so the two settings (`agility_url`, `agility_token`, sensitive, non-expiring) are carried verbatim
  under `extensions["io.github.mhidalgo-lab.agility-bridge"].userConfig`, each naming the variable it feeds.
- Root `mcp.json` (the spec's MCP location): stdio `npx -y agility-bridge@<version>`, no `env` (secrets in `env` are
  forbidden), generated by `agentPluginMcpJson` in `apps/cli/src/plugin-mcp.ts`.
- Root `skills` → `plugins/agility-bridge/skills` symlink: the spec discovers skills only there; nothing is copied.
- `scripts/release.ts sync-version [--check]` writes and checks the new manifest's version and `mcp.json`'s pin.
- The spec's two JSON Schemas vendored under `docs/schemas/agent-plugins/1.0.0/` and validated with Ajv in the test
  suite (CI); `ajv` added as a dev dependency.
- AGENTS.md: status line no longer names a version; new "Using agility-bridge from an agent" section.
- README: manifests listed, AGENTS.md described, author line linking <https://mhidalgo.ar/developers/>.
- GitHub topics `mcp`, `mcp-server`, `agent-skills`, `claude-code-plugin`, `digital-ai-agility`, `versionone`.

## Acceptance criteria
- [x] `plugin.json` and `mcp.json` validate against the published 1.0.0 schemas; a manifest with `userConfig` at the top
      level or an invalid name is rejected (tests).
- [x] Versions of `plugin.json`, `mcp.json`'s pin, `server.json`, the Claude Code plugin and the CLI package are equal
      (test); `sync-version` bumps both new files and `--check` fails when either lags (end-to-end test).
- [x] Metadata and settings equal the Claude Code manifest's, the token sensitive and "does not expire" (test).
- [x] `skills/` resolves inside the repository to the Claude Code plugin's skills, one `SKILL.md` each (test).
- [x] `claude plugin validate .` and `claude plugin validate plugins/agility-bridge` pass (Claude Code 2.1.332); a
      marketplace add + `plugin install agility-bridge@agility-bridge` from the checkout into an empty config directory
      installs 0.8.0 with both skills and asks for the two settings.
- [x] AGENTS.md status no longer goes stale; the commands it quotes exist (`client-config`, `/plugin …`).
- [x] The repository has the six topics (set 2026-11-27 with `gh repo edit`; it had none).
- [x] THREAT_MODEL (8l), RESEARCH (§3), L-509 and a changeset.

## Security notes
T23: `mcp.json` carries no `env`; the settings are described, never valued. T18: the package is pinned to the exact
version and kept in step by lint. Every file is scanned for secret shapes by the existing plugin test.

## Lessons applied
- L-435 — the new `mcp.json` is generated by the same module and compared with the committed file.
- L-509 — the portable format was read from its spec, not mapped from the Claude Code manifest.
