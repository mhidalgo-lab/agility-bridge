# Storage (`packages/storage`, `packages/storage-sqlite`)

Durable state for the remote modes: users, instances, credentials, workspaces, grants, device tokens, the audit log,
settings and short-lived `kv` records ([ADR-0006](../adr/0006-storage-sqlite-d1-yaml.md),
[ARCHITECTURE §4](../ARCHITECTURE.md#4-access-model)). stdio keeps no database.

| Piece | Where | Runtime |
|---|---|---|
| `Storage` interface, records, errors | `packages/storage/src/types.ts`, `errors.ts` | web |
| Column rules shared by every adapter | `packages/storage/src/fields.ts`, `kv-rules.ts` | web |
| Drizzle schema (SQLite dialect) | `packages/storage/src/schema.ts` | web |
| Embedded migrations and the runner | `packages/storage/src/migrations/`, `sql/migrate.ts` | web |
| SQL implementation over a `SqlDriver` | `packages/storage/src/sql/storage.ts` | web |
| `memory` adapter | `packages/storage/src/memory.ts` | web |
| Read-only view | `packages/storage/src/read-only.ts` | web |
| `node:sqlite` driver | `packages/storage-sqlite/src/driver.ts` | Node |
| D1 driver | P3-02 | Workers |

## Repository semantics

Every adapter behaves identically, and the contract suite (`packages/storage/test/contract.ts`) proves it: the memory
adapter runs it in `packages/storage`, the SQLite one in `packages/storage-sqlite`, D1 joins in P3-02.

| Situation | Result |
|---|---|
| `get` / `getBy…` of a missing row | `null` |
| `update` / `delete` of a missing row | `NotFoundError` |
| A duplicate id or unique value (email, IdP identity, instance URL, slug, token hash) | `ConflictError` |
| Deleting a row that others still reference | `ConflictError` ("revoke or disable it instead") |
| A bad value, an unknown or fixed field, a missing parent, a cross-row rule | `InvalidInputError` |
| A write through `readOnlyStorage(…)` | `ReadOnlyStorageError` |
| A database newer than the binary, or with a different migration history | `MigrationError` |

All of them extend `StorageError` (with a `code`). Messages name tables and columns, never values.

- Ids are generated by the caller; `createdAt` and `updatedAt` come from the storage clock (`now`, injectable).
- Records are copies: changing a returned object changes nothing stored.
- Fixed after creation (not patchable): ids, a credential's instance, owner and secret material, a workspace's
  instance, a grant's workspace and user, a token's grant, hash and `lastUsedAt` (written only by `touch`).
- Lists of ids and tools are JSON arrays of 1–256-character strings (at most 1,000); objects are JSON objects of at
  most 64 KiB; labels at most 200 characters without control characters.

### Cross-row rules (ADR-0008)

Enforced by triggers in SQL, so raw SQL writers are held to them too, and mirrored by the memory adapter:

- A workspace's default credential is a **shared** credential of the **workspace's instance**.
- A grant's credential belongs to the workspace's instance and is shared or **the grant user's own**; a service grant
  (no user, label required) can only use shared credentials (L-065).
- An instance's `baseUrl` and `tls` cannot change while it has credentials that are not revoked (THREAT_MODEL A14).
- `audit_log` rows are never updated (THREAT_MODEL T17); retention deletes whole rows.

### Deletion rules

| Delete | Effect |
|---|---|
| workspace | removes its grants and their device tokens |
| grant | removes its device tokens |
| credential | refused while a grant or a workspace default uses it |
| instance | refused while credentials or workspaces use it |
| user | refused while they own credentials or have grants |

Audit rows have no foreign keys and outlive what they describe.

### `kv`

Opaque string values with an optional absolute expiry (epoch ms); expired entries read as absent and are removed by
`purgeExpired`. Keys are 1–512 printable ASCII characters without spaces.

| Operation | Atomic guarantee |
|---|---|
| `setIfAbsent(key, value)` | of concurrent callers, exactly one stores (an expired entry counts as absent) |
| `take(key)` | of concurrent callers, exactly one gets the value (L-073); an expired entry is removed and not returned |
| `increment(key, { by, max, expiresAt })` | no lost updates; refused (`null`) when the result would pass `max`; `expiresAt` applies to a new or restarted counter |

## Conditional writes (L-072, L-161)

Every conditional write is **one statement** whose outcome is read from its `RETURNING` rows: `UPDATE … WHERE …
RETURNING`, `INSERT … ON CONFLICT DO UPDATE … WHERE … RETURNING`, `DELETE … RETURNING`. Never read-decide-write in
application code, and never decide on driver change counters (D1 counts cascaded rows, `node:sqlite` does not). The
memory adapter performs each operation without an `await` between its read and its write.

Bind integers in SQL arithmetic with `CAST(? AS INTEGER)`: `node:sqlite` binds JavaScript numbers as `REAL`, so
`value + ?` turns `'2'` into `'3.0'` (L-173).

## Migrations (L-071)

- Embedded TypeScript modules in `packages/storage/src/migrations/`, one SQL statement per array entry (D1 batches
  cannot split scripts; triggers contain semicolons). The DDL is written by hand: STRICT tables, CHECK constraints and
  triggers are beyond Drizzle's generator. `packages/storage-sqlite/test/sqlite.test.ts` checks that the migrated
  columns match `schema.ts` exactly.
- `migrate(driver)` (and `openSqlStorage`, which migrates first) applies each pending migration with its
  `schema_migrations` row in one batch: all or nothing. Two processes migrating at once end on the same history.
- Refused: a database with a version newer than the binary, a gap, or a checksum that differs (SHA-256 over version,
  name and statements). Released checksums are frozen in `packages/storage/test/migrations.test.ts`: fix a mistake with
  a new migration, never by editing a released one.
- **Database fixtures**: one SQL dump per released minor in `packages/storage-sqlite/test/fixtures/databases/`
  (synthetic rows in every table), loaded, migrated and exercised by `fixtures.test.ts`. Before a minor that changes the
  schema is released, generate its fixture once and never regenerate it:

  ```sh
  pnpm storage:fixture 0.3
  ```

  `0.2.sql` is the first; until v0.2.0 ships it may be regenerated together with migration 0001.

## Adding a migration

1. Add `src/migrations/NNNN-name.ts` with the next version and append it to `MIGRATIONS`.
2. Update `schema.ts`, the records in `types.ts` and the rules in `fields.ts`, then both adapters; add contract tests.
3. Add its checksum to `FROZEN` once the release that ships it is cut.
4. Keep D1 limits in mind (P0-09): no interactive transactions, 100 bound parameters per statement.

## SQLite driver (`packages/storage-sqlite`)

`createSqliteDriver(db)` wraps one `DatabaseSync` connection: it turns `PRAGMA foreign_keys` on (off by default on every
`node:sqlite` connection) and refuses the connection if that fails, caches prepared statements, binds values only as
parameters, and runs a batch as `BEGIN IMMEDIATE … COMMIT` (rolled back on any error). Opening files safely (mode
`0600`, WAL, busy timeout, backups) is P2-02.
