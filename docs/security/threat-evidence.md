## How to read it

| Level | Meaning |
|---|---|
| **A** | Automated in CI (`pnpm test`; in-memory and SQLite storage, workerd for the Worker, a real browser for `e2e/`), against fakes or fixtures that model Agility. |
| **A+L** | Automated as above, **plus** a part that only a live Agility tenant or a real MCP client can prove. That part is named in the last column and stays unproven until the owner runs it (never faked here). |
| **P** | Process or pipeline control, checked by a lint script or a workflow check, not by a runtime test. |

Residual risks are accepted explicitly in the register below (`R-n`); a row that points at an `R-n` has nothing left to
fix, only something to know. `Live` items are collected in the second register.

Each is a known limit that the project accepts for 1.0. It is stated in the threat model, in the guide where a user
decides on it, and here, so no one finds it by surprise.

| Id | Risk | Why it is accepted | Rows | Where it is documented |
|---|---|---|---|---|
| R-1 | The untrusted-data envelope reduces prompt injection; it does not eliminate it. | No output filter can; the real barrier is the approval of every write (ADR-0013) and the member's own Agility permissions. | T6, T31, A1 | THREAT_MODEL section 8; [write tools](../guide/write-tools.md) |
| R-2 | Elicitation is answered by the client, which may not prove that a human looked. | The approval page (`page_only`) is the stronger channel and can be required per grant or workspace. | T31, A13 | THREAT_MODEL section 8; write-tools guide |
| R-3 | Data returned to the client leaves our control (the LLM provider's retention). | Outside the product's reach; mitigated by tiers, asset-type allow lists and local-model guidance. | A11 | THREAT_MODEL section 8; [clients](../guide/clients.md) |
| R-4 | Per-isolate rate limits on Workers are approximate unless the optional Durable Object limiter is on. | The Rate Limiting binding backstops across isolates; the exact limiter is opt-in (P3-12) because it costs a request per check. | T1, T20 | [Cloudflare limits](../guide/cloudflare-limits.md) |
| R-5 | Workers cannot trust private CAs or reach private networks. | A platform limit; on-premises instances use the Node deployment. | A9 | THREAT_MODEL section 8 |
| R-6 | A process holding the master key can decrypt every stored token. | Inherent to envelope encryption with an operator-held key; the key is separate from the data and rotatable. | T7 | [secrets](../guide/secrets.md); [cryptography](cryptography.md) |
| R-7 | Instance URLs may point at private addresses by default. | On-premises instances need it; only owners and admins define instances and every change is audited; `AB_INSTANCE_PRIVATE_ADDRESSES=refuse` closes it. | A9 | THREAT_MODEL section 8 |
| R-8 | A bad token on a pass-through workspace answers after an Agility round trip, so a caller can tell which slugs are pass-through. | Padding the latency was judged not worth it; body and status are identical. | T19 | THREAT_MODEL section 8 |
| R-9 | An Agility token carries the member's full permissions; a stolen one can act directly against Agility. | We can narrow what the bridge does, not what Agility allows; tokens never leave encrypted storage and are revocable. | A5 | THREAT_MODEL section 3 and 8 |
| R-10 | A read-only grant beside a writing one can see up to one cache TTL of data from before the other grant's write. | The cache is off by default and capped at 60 s; the guide says so. | T16 | [query cache](../guide/query-cache.md) |
| R-11 | The MCP App view posts to `'*'` because a sandboxed host has an opaque origin. | The view is static and carries no data of its own; the host is the only peer. | T27 | THREAT_MODEL section 8i-4 |
| R-12 | The release chain trusts GitHub, npm and the registries' own controls (account takeover of a maintainer). | Mitigated by provenance, 2FA, pinned actions and a separate publish job; cannot be removed. | T18 | [verify a release](../guide/verify-release.md) |
| R-13 | With `AB_PUBLIC_TOOL_CATALOG` on, anyone can read the tool names and descriptions. | Opt-in, static, no instance data; the setting says so. | T33 | THREAT_MODEL section 8i-3 |
